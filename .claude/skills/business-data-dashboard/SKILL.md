# Business Data Dashboard Skill

비즈니스 거래 데이터(주문·물류·배송·구매·매출·고객·재고 등)를 받아 **대표 보고용 S급 엑셀 대시보드**를 만드는 스킬.

---

## 🚨 절대 규칙 (NON-NEGOTIABLE)

이 세 가지는 어떤 상황에서도 어긴다 → 작업 실패로 간주한다.

### 규칙 1: 스킬 로드 직후 첫 응답
이 스킬을 처음 읽은 직후, 사용자가 아직 데이터를 주지 않았거나 요구사항만 말한 상태라면 **반드시 다음 한 문장으로 응답**한다:

> **"준비가 되었으니 데이터를 넣어주세요."**

이 문장 앞뒤로 짧은 도입(예: "분석에 필요한 작업 환경 세팅 완료했습니다.")은 허용하지만, 데이터 형식이나 칼럼에 대한 질문을 먼저 던지지 않는다. 데이터를 받고 나서 클렌징하면서 자연스럽게 파악한다.

### 규칙 2: 오류 0건 검수
엑셀 파일을 저장한 직후 **반드시** 두 단계 검수를 거친다:

1. **수식 재계산 검수**: `python /mnt/skills/public/xlsx/scripts/recalc.py <파일경로>` 실행
   - `status: "errors_found"` 면 즉시 수정 후 재실행. `status: "success"` 나올 때까지 반복.
   - `total_formulas`가 예상보다 적으면 시트 누락 또는 셀 참조 오류 의심.

2. **계산값 검증**: `data_only=True`로 파일을 다시 열어 핵심 KPI(총합·평균·비율 등)를 출력해 **수동 검산**한다.
   - 예: 총매출 = 완료 상태인 행의 금액 합과 일치하는지
   - 예: 비중 합계가 100.0%인지
   - 예: TOP N 정렬 순서가 실제 금액 순서와 일치하는지

검수에서 발견한 오류는 **인사이트 본문 수치까지** 함께 수정한다. (수치만 고치고 본문에 옛 수치가 남아있으면 안 됨)

### 규칙 3: 도메인 범용성
이 스킬은 주문 데이터에만 쓰이지 않는다. 받은 데이터의 컬럼을 **자동 감지**해서 도메인을 판별하고, 그에 맞는 용어·표·인사이트를 생성한다. 도메인별 매핑은 [도메인 적응 가이드](#도메인-적응-가이드) 참조.

## 📊 핵심 워크플로우 (5단계)

순서를 지킨다. 각 단계는 다음 단계의 입력이다.

### 1단계 - 클렌징
받은 데이터의 컬럼을 자동 감지하고, 다음 패턴을 찾아 정리:

| 카테고리 | 흔한 오류 패턴 | 처리 방식 |
|---|---|---|
| 연락처 | 하이픈 누락(`01012345678`), 형식 혼재 | 11자리면 `010-XXXX-XXXX`로 통일 |
| 이메일 | `@@` 중복, 도메인 누락(`@gmail`) | `@@`→`@`, 도메인에 점 없으면 `.com` 추가 |
| 날짜 | `YYYY/MM/DD`, `MM-DD-YYYY` 혼재 | `YYYY-MM-DD`로 통일 |
| 결측 담당자 | 빈 칸, 공백만 | 같은 지역의 주 담당자 자동 배정 (도메인별 룰 적용) |
| 결측 배송일/입고일 | 공란 | 상태값과 정합성 확인 후 그대로 둠 |

원본값과 수정값을 **모두 보관**한다 (클렌징 리포트 시트에서 Before/After 비교용).

### 2단계 - 검증
- **금액 검증**: `수량 × 단가 = 총금액` 일치 여부 (`✓ 정상` / `✗ 불일치`)
- **중복 식별**: 동일 고객/거래처가 여러 행에 있는지 COUNTIF로 카운트
- **이메일 형식**: 정규식 `^[^@\s]+@[^@\s]+\.[^@\s]+$` 통과 여부

### 3단계 - 파생 컬럼
원본 데이터 옆에 다음 6개 분석용 컬럼을 추가:

1. **금액검증** - `=IF(수량셀*단가셀=총금액셀,"✓ 정상","✗ 불일치")`
2. **금액 구간** - `=IF(총금액>=임계값,"고액","일반")` (임계값은 데이터 분포에서 결정, 보통 평균의 2배 또는 100만원)
3. **VIP/주요 거래처 여부** - `=IF(SUMIFS(금액열,고객열,현재고객,상태열,"완료")>=VIP_임계값,"⭐ VIP","일반")` ← **반드시 SUMIFS로 완료 상태만 합산** (취소·실패 제외)
4. **지연 여부** - 두 날짜 차이가 임계일 초과 시 `⚠ N일`, 미배송이면 `미배송`
5. **결제/방식 그룹** - 카드/현금, 직배송/택배 등 도메인별 그룹화
6. **데이터오류** - 클렌징 단계에서 수집한 오류 플래그 (정상이면 "정상")

### 4단계 - 집계/피벗
대시보드 시트에 다음 표를 **항상 같은 폭으로** 배치:
- 지역별 (또는 거점별)
- 카테고리별 (또는 품목별)
- 담당자별 (또는 거래처별)
- 결제수단별 (또는 운송수단별)
- TOP 5

각 표에는 **금액·비중·시각화 막대(REPT)·비고** 4컬럼 패턴을 적용.

### 5단계 - 인사이트
6개 발견점을 **표 형식**으로 작성. 각 인사이트는:
- **제목** (이모지 + 핵심 문장)
- **우선순위** (🔴 높음 / 🟡 중간 / 🟢 낮음)
- **핵심 수치** (한 줄 요약)
- **시급도** (즉시 / 이번 주 / 이번 달 / 다음 분기)
- **발견** (3~4문장 분석)
- **액션** (3~4문장 구체적 조치)

**수치는 검산을 통과한 값만 사용**한다. "약 64.7%" 같은 수치는 실제 계산값과 일치해야 한다.

## 📁 4시트 구조 (필수)

순서를 지킨다. 사용자가 첫 화면에서 봐야 할 시트가 1번이다.

| 순서 | 시트명 | 역할 |
|---|---|---|
| 1 | 📊 대시보드 | KPI 4종 + 5개 집계 표 + 차트 2개 |
| 2 | 데이터(클렌징) | 클렌징 완료된 원장 + 파생 컬럼 6개 + 필터 |
| 3 | 🔍 클렌징 리포트 | 요약 표 + 행 단위 Before/After |
| 4 | 💡 인사이트 | 요약 표 + 6개 상세 표 |

시트 정렬은 다음 코드로:
```python
desired_order = ["📊 대시보드", "데이터(클렌징)", "🔍 클렌징 리포트", "💡 인사이트"]
wb._sheets = [wb[name] for name in desired_order]
wb.active = 0
```

데이터 시트명은 도메인에 맞게 변경 가능 (예: `주문데이터(클렌징)`, `배송데이터(클렌징)`, `구매데이터(클렌징)`).

## 🎨 디자인 시스템 (절대 변경 금지)

자세한 색상 팔레트와 스타일 함수는 `references/design-system.md` 참조. 핵심만 요약:

- **메인 헤더**: 진한 네이비 (`#1F3864`) + 흰 글씨 + 굵은 medium 테두리
- **데이터 행**: 부드러운 블루 톤 얇은 테두리 (`#8FAADC`)
- **줄무늬**: 짝수 행에 연한 파랑 배경 (`#DDEBF7`)
- **합계 행**: 연한 그린 배경 (`#E2EFDA`) + 네이비 굵은 테두리
- **시각화 막대**: `=REPT("■",ROUND(비중*30,0))` 패턴, 표마다 다른 색상으로 구분
- **폰트**: 맑은 고딕 통일

**대시보드 표는 모두 같은 폭(B~I 8컬럼)으로 위→아래 정렬**한다. 좌우로 표를 흩지 않는다.

## 🔧 도메인 적응 가이드

받은 데이터의 컬럼명을 보고 도메인을 자동 판별:

| 도메인 신호 | 컬럼 키워드 | 매핑 |
|---|---|---|
| **주문 데이터** | 주문ID, 고객, 상품, 결제 | 그대로 사용 |
| **배송 데이터** | 송장번호, 운송장, 출발지, 도착지, 기사 | 고객명→수령인, 담당자→기사명, 결제수단→운송수단 |
| **물류 데이터** | 입고일, 출고일, 창고, SKU, 재고 | 주문일→입고일, 배송일→출고일, 지역→창고 |
| **구매 데이터** | 발주번호, 거래처, 입고예정일, 단가 | 고객→거래처, 주문일→발주일, 배송일→입고일 |
| **매출 데이터** | 거래일자, 영업사원, 채널 | 담당자→영업사원, 지역→채널 |
| **CRM 데이터** | 리드, 상담, 전환, 영업단계 | 상태→영업단계, 금액→예상매출 |
| **재고 데이터** | 품목, 입고, 출고, 현재고, 안전재고 | 수량→현재고, 카테고리→품목군 |

**도메인별 인사이트 톤**도 다르다:
- 주문/매출 → "VIP", "취소율", "재구매율"
- 배송/물류 → "지연율", "운송 효율", "거점별 처리량"
- 구매 → "거래처 의존도", "납기 준수율", "단가 변동"
- 재고 → "회전율", "안전재고 미달", "데드스톡"

받은 데이터 컬럼이 위 표에 명확히 매핑 안 되면 **컬럼명 그대로 사용**하고, 비즈니스 의미는 데이터 분포에서 추론한다.

## 💻 구현 패턴

빌드 시 사용할 코드 템플릿은 `references/build-template.py`에 있다. 새 데이터를 받으면:

1. `references/build-template.py`를 읽어 구조 파악
2. `raw_data` 부분만 받은 데이터로 교체
3. 도메인별로 컬럼명·시트명·인사이트 본문만 수정
4. 빌드 → recalc → 검산 → 사용자에게 제시

**수식은 절대 Python에서 계산해서 하드코딩하지 않는다.** 항상 Excel formula로 작성해서 데이터 변경 시 자동 재계산되게 한다.

### 자주 쓰는 수식 패턴

| 용도 | 수식 |
|---|---|
| 조건 합계 | `=SUMIFS(금액열, 분류열, "값", 상태열, "완료")` |
| 조건 카운트 | `=COUNTIFS(분류열, "값", 상태열, "완료")` |
| 평균 (조건) | `=AVERAGEIFS(금액열, 상태열, "완료")` |
| 비중 | `=IFERROR(C{r}/$C$합계행, 0)` |
| 시각화 막대 | `=REPT("■", ROUND(비중*30, 0))` |
| 행 카운트 | `=COUNTA(A:A) - 헤더행수` (안내 1행 + 헤더 1행이면 -2) |
| 날짜 차이 | `=IF(F{r}="", "미발송", IF(F{r}-E{r}>3, "⚠ "&(F{r}-E{r})&"일", F{r}-E{r}&"일"))` |

### 행 인덱스 주의사항

데이터 시트는 항상 다음 구조로:
- **1행**: 안내 메시지 (병합)
- **2행**: 컬럼 헤더
- **3행~**: 데이터

따라서 첫 데이터 행의 수식은 `=IF(I3*J3=K3,...)` 같이 **3을 참조**한다. KPI 합계는 `=COUNTA(A:A)-2`. 행 삽입 후 수식을 작성하면 참조가 어긋나므로 **순서: 안내행 먼저 → 헤더 → 데이터+수식 동시**로 작성한다.

## 📝 인사이트 작성 가이드

### 발견점 톤
- 단정적이고 짧게. "~할 수 있다" 보단 "~하다".
- 수치는 반드시 검산 통과한 값.
- 데이터 한계도 솔직히 명시 (예: "1004번은 담당자 공란이라 자동 배정한 값임").

### 액션 톤
- 동사로 시작 (검토하다 / 도입하다 / 분석하다 / 발송하다).
- 측정 가능한 형태 (예: "분기 1회 점검", "24시간 내 컨펌 콜").
- 너무 두루뭉술한 "전반적 개선" 같은 표현 금지.

### 우선순위 배분
- 🔴 높음 2~3개 (당장 매출/리스크에 영향)
- 🟡 중간 2~3개 (이번 분기 내 처리)
- 🟢 낮음 1~2개 (장기 개선)

## 🚫 금지 사항

- 수치만 고치고 인사이트 본문에 옛 수치 남겨두기 (반드시 함께 수정)
- VIP 판정 시 취소·실패 상태 포함 (반드시 완료 상태만)
- 큰따옴표(`"`) 사용 (사용자 메모리 규칙: 한국어 본문에는 따옴표 금지). 단, **엑셀 수식 내부의 큰따옴표는 문법상 필수이므로 허용**.
- Python에서 계산값 하드코딩 (반드시 수식)
- 셀 병합 후 `insert_rows` 사용 (참조 어긋남 위험)
- 차트를 표 영역 사이에 배치 (오른쪽 K열 이후로)
- 검수(recalc + 검산) 건너뛰고 파일 제출

## ✅ 빌드 후 체크리스트

파일 저장 후 사용자에게 제시하기 **전에** 반드시 통과:

- [ ] `recalc.py` 실행 결과가 `status: success`
- [ ] 핵심 KPI 검산 일치 (총매출·주문건수·평균·비율 등)
- [ ] 비중 합계가 100.0%
- [ ] TOP N 정렬이 실제 금액 순서와 일치
- [ ] VIP 판정이 완료 상태 기준
- [ ] 인사이트 본문의 수치가 표의 수치와 일치
- [ ] 시트 순서: 대시보드 → 데이터 → 클렌징리포트 → 인사이트
- [ ] 첫 화면이 대시보드 (`wb.active = 0`)
- [ ] 한국어 본문에 큰따옴표 없음
