# 네이버 블로그 글쓰기 — 업종 무관

> 한 안경원 블로그를 몇 달 운영하며 운영자에게 교정받은 것을 업종 무관으로 정리한 스킬이다.
> 목표는 세 가지 — ① 사실만 쓴 글 ② 휴대폰에서 읽기 쉬운 서식 ③ 운영자가 «복사 → 붙여넣기 → 사진 올리기 → 발행»만 하면 끝나는 상태.
> ★ 프로젝트에 자체 블로그 규칙(예: `docs/규칙/블로그_*.md`)이 있으면 **그쪽이 우선**이다. 이 스킬은 바닥 규칙과 도구다.

## 하는 일 / 하지 않는 일
| 한다 | 하지 않는다 |
|---|---|
| 업체설정 정리 · 사실 조사 · 원고 · 검사 · 복사용 페이지 · 사진 가리기·표시·가운데 맞춤 · 발행 순서 안내 | 네이버 로그인·발행 대행 · 자동 발행 프로그램(약관 위반) · 사진 폴더 경로 추측 · 출처 없는 사실 |

## 0. 먼저 — 업체설정 (없으면 만든다)
1. 업체 작업 폴더에서 `블로그_업체설정.md`(또는 BRAND.md 같은 브랜드 문서)를 찾는다.
2. 없으면 `references/업체설정_템플릿.md` 를 복사해 만든다. 빈 칸은 **운영자에게 묻는다** — 한 번에 묻고 짧게:
   상호·지역 낱말·주소/전화(통일 표기) · 업종 · 주 손님 · 확인된 강점(경력·자격·장비) · 요일별 글 종류 · 사진 폴더 · 얼굴 노출 가능 여부
3. 업종 법적 금지선: `references/업종별_금지선.md` 에서 찾아 **법령 원문을 확인**하고 업체설정 «금지어» 표로 옮긴다(도구가 막는다).

## 2. 꼭 지키는 것 (상세는 references)
1. **사진에 없는 것을 쓰지 않는다.** 쓰기 전에 사진을 직접 연다.
2. **출처 없는 사실을 쓰지 않는다.** 잘 쓴 남의 블로그도 출처가 아니다. 모르면 빼고 «미확인»이라고 운영자에게 알린다.
3. 실사진 우선 → 공개 라이선스 → AI 는 글당 1장(«AI 활용» 표시). 가격표·얼굴·번호판은 가린다.
4. 휴대폰 서식: 한 줄 18~20자(이야기형 24자) · 문단 2~4줄 · 가운데 정렬 · 문단마다 강조 하나 · 색은 전부 굵게.
5. 말투는 글 종류로: 설명형 «~요/~습니다» 섞기, 이야기형 합쇼체 다큐 해설.
6. 금지: 이모지 · 호객(초특가·득템·역대급·강추·놓치지 마세요) · 근거 없는 최상급 · 다른 업체 비교·비방 · 은유 · 하루 따라가기 서사 · 업종 법 금지 표현.
7. 키워드는 문장 속에 3~5번, 형태를 바꿔. 상호 정식 이름은 첫 등장 1번.
8. 같은 뼈대 연속 ✗ · 같은 주인공 3회 연속 ✗(그러면 쓰지 말고 운영자에게 알린다) · 대표 사진 재사용 ✗ · 다른 채널과 문장 복붙 ✗.
9. 글 끝은 늘 같은 «찾아오시는 길»(상호·주소·전화 통일 표기) + 이야기형은 «참고와 사진 출처».
10. 대가(협찬·체험단)가 있으면 제목 또는 첫 부분에 밝힌다.

## 3. 도구 — scripts/blogkit.py
```
python ~/.claude/skills/naver-blog-writer/scripts/blogkit.py <글폴더> [--rules <업체설정.md>] [--check]
```
- 글폴더: `글.md` + (선택) `사진.json`(또는 `표시.json`) + 원본 사진들
- 결과: `<글폴더>/복사용.html`(제목·태그·본문 복사 단추, 사진 순서표) · `<글폴더>/올릴사진/`(가린·표시 붙인·잘라낸 사진)
- 종료코드 0 통과 / 2 ✗ 있음(페이지 안 만듦). ⚠ 는 하나씩 읽고 판단한다(무시할 땐 이유를 안다)
- 필요: Python 3.9+, Pillow. `center` 는 rembg(선택, `pip install rembg`)
- 사진은 붙여넣기로 안 올라간다(링크로만 남음) → 페이지의 파란 «사진 자리»에 운영자가 사진 버튼으로

## 4. 운영자에게 넘기는 것 (비전문가가 읽는다 — 표·짧게)
1. 복사용 페이지 경로(더블클릭으로 열림) · 올릴 사진 폴더
2. 발행 순서: ① 제목 복사 ② 본문 전체 복사 → 붙여넣기 ③ 사진 자리마다 사진 버튼 ④ 인용구 모양 고르기 ⑤ 글씨체 확인 ⑥ 태그 ⑦ AI 표시(해당 시) ⑧ 예약 발행
3. **사실 확인표** — 위험도별(높음: 가격·효능·법·수치 / 중간: 연도·인물·소속 / 낮음: 묘사) 각 줄의 출처 URL 또는 «사진 N 육안 확인»
4. 미확인으로 뺀 것, 운영자가 정해야 할 것(따로 한 줄씩)

## 5. 운영하며 배운 것 — 같은 지적을 두 번 받지 않으려고
| 겪은 일 | 그래서 |
|---|---|
| 사진을 안 열고 «저녁 산책»이라 썼는데 한여름 낮 사진이었다 | 쓰기 전에 사진부터 연다 |
| 서식을 손으로 꾸미느라 한 편에 30~40분 | 서식은 원고 문법 + 복사용 페이지로 미리 입혀 넘긴다 |
| «강조가 부족하다» → «문단마다 하나» 하한선을 둔 뒤 해결 | 서식 규칙은 숫자로 정하고 도구가 검사한다 |
| 전 글엔 테두리 강조를 했는데 다음 글에서 빠졌다 | 새 규칙은 기억이 아니라 **도구 검사**에 넣는다 |
| 같은 규칙이 문서 두 곳에 있어 옛 규칙이 먼저 읽혔다 | 규칙은 한 곳에만, 나머지는 그 파일을 가리킨다 |
| AI 사진 비중이 높던 시기 → «점수를 깎는 것 같다» | 실사진 중심으로 전환, AI 는 최후 1장 |
| 대표 사진이 지난 글과 같았다 | 대표 사진은 지난 글과 대조한다 |
| 운영자가 좋다고 한 레퍼런스 글에도 사실 오류·무단 사진이 있었다 | 레퍼런스는 구조·말투만 배운다 |
| «이 틀에서 벗어나고 싶다»고 줬는데 레퍼런스대로 썼다 | 레퍼런스를 받으면 «따라 하기»인지 «벗어나기»인지 먼저 묻는다 |
| «가운데 맞춰 달라»에 상자만 맞췄더니 주인공이 처져 보였다 | 정렬은 눈으로 본 주인공 기준으로 확인한다 |
| 트래픽용 무관 키워드 글 제안 | 업종 주제 밖 글은 쓰지 않는다(주제 집중·체류시간) |
| 민감 숫자를 전부 막았더니 잘 되는 글(무게 숫자 제목)을 못 썼다 | 전면 금지 대신 «공식 출처 + URL» 이면 허용 |
| 붙여넣기 실측: 색·굵게·형광·글자 크기·정렬·인용구·구분선·나눔고딕은 산다 / 사진은 링크로만 남는다 / 표·테두리는 미확인 | 새 플랫폼·새 서식은 첫 글에서 실측하고 업체설정에 적는다 |

## 6. 끝낼 때 확인
- [ ] 도구 ✗ 0, ⚠ 는 하나씩 판단
- [ ] 사진을 직접 열어 본 목록과 본문 묘사가 맞다 · 가릴 것 가렸다
- [ ] 숫자·연도·인용마다 출처가 있다(이야기형은 «참고» 절)
- [ ] 소리 내어 읽기 — 같은 끝맺음 연속·과장어·은유 없음
- [ ] 업체설정 «발행 기록»·«운영자 교정»에 한 줄씩
