# 한비즈마케팅 지원사업 안내글 작성 스킬

한국중소기업 비즈니스센터(한비즈마케팅)가 운영하는 네이버 카페(계약 체결 대표님 전용)에 게시할 정부·지자체 지원사업 안내글을 작성한다. 핵심은 **PDF 원문 100% 충실 + 정중한 공식체 + 항목별 번호 구조 + 즉시 복사·붙여넣기 가능한 완성도**다.

## 절대 원칙 (Non-negotiable)

1. **할루시네이션 0%**: PDF 원문에 적혀있지 않은 정보는 절대로 추가하지 않는다. 추정·일반화·상식적 보완 금지.
   - 제출서류, 신청절차, 문의처 등이 원문에 명시되지 않았다면 임의로 채우지 말고 "원문 미기재" 표기 또는 생략
   - "보통 이런 경우…", "일반적으로…" 같은 추정 문구 금지
2. **모든 숫자는 원문 그대로**: 지원금액, 기간, 금리, 상시근로자 수, 매출액 기준 등 단 하나의 숫자도 변경 금지
3. **모든 기관명·전화번호·주소는 원문 그대로**: 띄어쓰기, 한자, 영문 표기까지 동일하게
4. **작성 직후 PDF 재검토는 필수**: 모든 게시글 작성 후 반드시 ✅/❌ 형태로 자가 검증 결과 제시

## 표준 게시글 구조

게시글은 반드시 아래 구조를 따른다.

### 도입부 (고정 템플릿)

```
안녕하세요. 한국중소기업 비즈니스센터입니다. [N월 N주차] 기준으로 현재 접수가 진행 중인(자금/예산 소진 시까지) 주요 지원사업을 아래와 같이 안내드립니다. 각 사업별 상세 내용 및 신청서 양식은 첨부된 공고문을 반드시 함께 확인해주시기 바랍니다.
```

- 주차 표기: 게시 시점 기준 실제 주차 (예: 5월 첫째 주 월요일 게시 → "[5월 1주차]")
- 상시 접수형 사업: "(자금/예산 소진 시까지)" 포함
- 기간 한정형 사업: "(자금/예산 소진 시까지)" 부분 제외 가능

### 본문 - 사업별 상세 (항목 번호 구조)

각 사업은 아래 번호 순서를 따른다. **원문에 해당 정보가 없으면 해당 항목 자체를 생략**한다 (없는 정보를 추정해서 채우지 않는다).

```
**1. [정확한 사업명] ([주요 키워드/변경사항 요약])**

① 사업명 / 지역
[정확한 사업명] / [지역 또는 '전국']

② 지원대상
[원문 기재 내용 그대로]

《지원제외》
- [원문 기재 제외 사항]

③ 지원내용
[원문 기재 내용 그대로 - 금리/대출기간/상환방식/취급은행 등]

④ 지원금액
[원문 기재 한도]
- 매출액 구간별/유형별 한도가 있으면 모두 명시

⑤ 신청기간
[원문 기재 기간]

⚠️ [상시 접수형/예산 한정형 사업의 경우 자금 잔여 확인 안내 박스]

⑥ 신청방법
[원문 기재 방법 - 온라인 URL 정확히, 방문처 주소 정확히]

⑦ 제출서류
[원문 기재 서류만 - 추정 금지]

⑧ 지원절차 (또는 추진절차)
[원문 기재 절차 4~5단계]

⑨ 기타 유의사항
[원문 기재 유의사항]

⑩ 문의처
[기관명, 주소, 전화번호 정확히]
```

### 마무리 (고정 템플릿)

```
신청 접수에 관심이 있으신 대표님들께서는 계약/업무 담당자에게 요청 주시거나, 기업 카카오톡방에 내용 남겨주시면 담당 컨설턴트가 요건 검토 후 개별 안내드릴 수 있도록 하겠습니다.

⚠️ 더 자세한 사항은 첨부파일을 반드시 참고해주시고, 문의 사항이 있으신 경우 댓글 남겨주세요!
```

## 말투·표현 규칙

### 사용해야 하는 표현
- 어미: ~드립니다, ~주시기 바랍니다, ~해주세요
- 호칭: "대표님들께서는" (회원이 모두 사업체 대표이므로)
- 기호: ⚠️ (주의·강조), ※ (부가설명·조건), 《지원제외》, ① ② ③ ④ ⑤ ⑥ ⑦ ⑧ ⑨ ⑩
- 강조 굵게: **사업명**, **변경사항**, **핵심 수치** 등 시각적 강조가 필요한 부분만

### 절대 사용하지 않는 표현
- 따옴표 " " ' ' (한비즈마케팅 전체 룰)
- 장식 기호 (━━━, →, 박스형)
- 영상·블로그 톤 (구어, 감탄사, 이모지 남발)
- 추정·일반화 ("보통 이런 경우…", "일반적으로…")

### 이모지·기호 사용 제한
- ⚠️: 1회 (신청기간 강조) + 1회 (마무리 첨부파일 안내) = 최대 2회
- ※: 부가설명 시 자유롭게 사용 (원문 그대로 가져올 때)
- 그 외 이모지 일절 금지

## ⚠️ 안내 박스 사용 패턴

### 자금/예산 소진형 사업 (가장 빈번)
```
⚠️ 본 사업은 [자금/예산] 소진 시까지 순차 접수되는 사업으로, 접수 전 아래 ⑩ 문의처에 **[자금/예산] 잔여 여부를 반드시 사전 확인**하시기 바랍니다.
```

### 신규 공고 + 조기 마감 우려 (공고 후 1주일 이내)
```
⚠️ 본 사업은 공고일([날짜])부터 **[자금/예산] 소진 시까지 선착순 접수**되는 사업으로, 통상 [사업 유형]은 **조기 마감 가능성이 매우 높습니다**. 접수가 되었더라도 사업비 소진으로 지원 불가할 수 있으니 **빠른 신청을 권장**드립니다.
```

### 한정 인원·기간 사업
```
⚠️ 본 사업은 **총 [N]명/[N]건 한정** 사업으로, 사업 시작 후 [N]개월이 경과한 시점입니다. 신청 전 아래 ⑩ 문의처에 **[자금/예산/인원] 잔여 여부를 반드시 사전 확인**하시기 바랍니다.
```

## 작성 후 자가 검증 (필수 단계)

게시글 작성 직후 반드시 아래 형태로 PDF 원문 대조 결과를 제시한다.

```
---

**📋 작성 후 PDF 재검토 결과 (할루시네이션 검증)**

첨부된 공고문 원문과 작성한 글을 항목별로 정밀 대조한 결과, 원문에 없는 정보는 포함되지 않았음을 확인했습니다.

✅ **원문 기재 정보만 사용했는지 검증 완료**
- 공고번호([번호]) 근거 사업명 ✓
- [지원금액 등 핵심 수치] ✓
- [신청기간] ✓
- [지원대상 요건] ✓
- [지원제외 N가지] ✓
- [제출서류 N종] ✓
- [문의처 N개소 전화번호] ✓
[... 모든 주요 항목 ✓ 체크]

❌ **원문에 없어 작성하지 않은 항목** (있을 경우만 기재)
- [항목명] → 원문 미기재로 생략

원문에 없는 추정 정보나 임의 추가된 내용은 없으며, 네이버 카페에 바로 복사·붙여넣기 가능합니다.
```

## 사용자가 "한 번 더 확인" / "재확인" 요청 시 대응

사용자가 "혹시 모르니까 한 번 더 확인", "재확인", "정말 원문이랑 일치하는지 봐줘" 등을 요청하면:

1. **이전 작성본을 원문과 다시 정밀 대조**
2. **이전에 놓친 항목이 있으면 솔직히 발견 사실 보고** (예: "정밀 재검토 중 N가지 보완할 점을 발견했습니다")
3. **보완 사항을 반영한 수정본 즉시 제시**
4. **최종 검토 결론** 명시 ("이제 모든 정보가 누락 없이 반영되었습니다")

이때 절대 "이전 글이 완벽했습니다"라고 방어적으로 답하지 말 것. 사용자의 재확인 요청은 보완할 점이 있는지 한 번 더 보라는 신호이므로, 정말로 한 번 더 정밀 대조해야 한다.

## "딥리서치" 요청 시 대응

사용자가 "딥리서치", "지금 신청 가능한지 확인", "공식 출처 교차 확인" 등을 요청하면:

### 1단계: 웹 검색으로 공식 출처 확인
- `web_search`로 "[YYYY년] [지자체명] [사업명] 공고" 등 검색
- 공식 기관 홈페이지(go.kr, or.kr) 우선 확인
- 보도자료·언론보도로 교차 검증

### 2단계: 검증 결과 정리 (citation 활용)
```
## 🔍 딥리서치 검토 결과

### ✅ 1. 현재 신청 가능 여부 - **[신청 가능/마감 임박/마감]**
[공식 출처 인용 + 현재 상태 명시]

### ✅ 2. 작성한 글의 정확성 검증
[표 형태로 항목별 일치 여부 - antml:cite 활용]

### ⚠️ 3. 발견된 이슈 (있을 경우)
[수정 권장 사항]

### 📌 4. 최종 결론
✅ **할루시네이션 없음**
✅ **현재 신청 가능 여부**
✅ **수정 사항** (있을 경우)
✅ **즉시 게시 가능 여부**
```

### 3단계: 회원 대표님 안내 권장사항 제시
- 사업 시작 후 경과 기간에 따라 "잔여 자금/인원 사전 확인 권장" 안내
- 공식 문의처 전화번호 다시 한 번 강조

## "논란 여지 확인" 요청 시 대응

사용자가 "이대로 게시해도 논란 없는지", "법적 문제 없는지", "꼼꼼히 한 번 더 봐줘" 등을 요청하면 아래 8가지 체크포인트를 모두 점검:

1. **수치 정확성**: PDF 원문과 100% 일치
2. **기관명·연락처 정확성**: 띄어쓰기·전화번호 정확
3. **개인정보·금융정보 노출 위험**: 계좌번호·주민번호 등 노출 없음
4. **저작권**: 공공기관 공고문 인용 범위 내
5. **차별·혐오 표현**: 없음
6. **과장·오해 소지**: PDF 범위 내 표현
7. **시기 표현 오류**: 게시 주차 표기, 신청기간 정확성
8. **URL·도메인 클릭 가능 여부**: 한글 도메인 경우 "주소창 직접 입력" 안내 추가

## 추가 시나리오별 대응

### 변경공고 (추경 반영 등)
- 도입부에 변경 사항 요약 박스 추가:
```
📌 본 공고는 **[변경 사유 요약]**이 반영되어 변경된 공고입니다.

🔔 **[주요 변경사항 요약]**
- [항목 1]: **+[금액]** 증액
- [항목 2]: **+[금액]** 증액
- 총 변경 규모: **+[합계]**
```
- 변경된 자금/항목만 집중하여 안내 (전체 공고를 다 안내하지 않음)

### 여러 사업 동시 안내
- "1. 사업명 / 2. 사업명 / 3. 사업명" 식으로 번호 매김
- 각 사업별 ①~⑩ 구조 동일하게 반복
- 사업 간 구분은 `---` 가로선으로

### 회원 카페 외 일반 게시판용 작성 요청 시
- 본 스킬은 **계약 체결 대표님 전용 카페**가 기본 전제
- 일반 게시판용 요청 시: "계약/업무 담당자" 문구를 "기업/공식 채널"로 자연 수정

## 작업 흐름 (Workflow)

```
1. 사용자가 PDF 첨부 + 게시글 작성 요청
   ↓
2. PDF 원문 정밀 독해 (모든 페이지)
   ↓
3. 표준 구조에 맞춰 게시글 작성
   - 원문에 있는 정보만 사용
   - 원문에 없는 정보는 생략
   ↓
4. 게시글 작성 직후 자가 검증 결과 제시
   - ✅/❌ 항목별 체크
   ↓
5. (요청 시) 딥리서치 - 웹 검색으로 공식 출처 교차 검증
   ↓
6. (요청 시) 논란 여지 점검 - 8가지 체크포인트
   ↓
7. (요청 시) 보완 사항 반영한 최종본 제공
```

## 주의사항 (자주 하는 실수)

- ❌ 제출서류가 원문에 없는데 일반적인 서류 목록으로 채우기
- ❌ "자금 소진 시까지 순차 접수" 같은 표현을 원문에 없는데 추가하기
- ❌ 신청기간 표현을 "보통 1개월 이내" 식으로 추정
- ❌ 게시 주차 표기를 정확히 계산하지 않고 작성
- ❌ ⚠️ 이모지를 3회 이상 남용
- ❌ "이전 게시글과 동일한 형식으로" 작성하면서 새 PDF의 정보를 검증하지 않음
- ❌ 한글 도메인(예: 행복카드.kr) 안내 시 클릭 불가 위험 미고지
- ❌ 사용자가 "재확인" 요청했을 때 방어적으로 "완벽했다"고 답하기

## 마무리

이 스킬은 **PDF 원문 충실성 + 정중한 공식체 + 자가 검증**이 핵심이다. 어떤 경우에도 원문에 없는 정보를 임의로 채우지 말고, 작성 후 반드시 자가 대조 검증 결과를 함께 제시한다. 사용자의 "재확인" 요청은 진짜로 재확인하라는 신호임을 잊지 말 것.
